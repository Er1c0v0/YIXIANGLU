# 内容维护

| 路径 | 用途 |
| --- | --- |
| `hexagrams/01.json`～`64.json` | 每卦正文、意象、注记与既有白话档案 |
| `reviews/01.json`～`64.json` | 同编号卦的逐条审核，含原文、说明及爻位档案 |
| `reviews/methods.json` | 共用核对流程、日期和共同问题，不提供状态默认值 |
| `search.json`、`reviews/search.json` | 检索词、拼音、结构关联及审核 |
| `classroom.md` | 独立课堂取象原表，供来源引用与逐格比对 |
| `imagery.json`、`elements.json`、`reviews/trigrams.json` | 八卦对应、生克及审核 |
| `sources.json` | 采用版本、对校版本、段落与权利说明 |
| `manifest.json` | 构建生成的版本、计数和待审清单 |

卦ID、正文ID、审核ID保持稳定。`manifest.json`及`miniprogram/data/`中的`content.ts`、`search.ts`、`trigrams.ts`、`sources.ts`由构建器生成，不手改；页面只读本地资料。正文、检索及速查模块裁剪为运行字段；正文块和意象条目的ID、原文白话、notes、审核编号、爻位说明、爻的`polarity`、特殊知识说明与不展示的先天数/方位留在本目录。`sources.ts`只打包正文和概述实际引用的来源，每条保留完整版本、署名与许可；全部来源登记仍在本目录的 `sources.json`。界面仅取标题、定位及网址。数据版本与构建哈希由`manifest.json`记录，运行模块不再重复导出未使用的`DATA_VERSION`和`BUILD_HASH`。964个原文块、展示说明及原文来源定位继续随包保留。

独立详情、生成与分析页共用 `miniprogram/data/repository.ts` 和阅读组件，不另复制正文。目录与翻阅按当前卦ID读取资料，结果快照只保存有序卦ID及筛选标记；运行字段精简不改变内容源、清单或审核状态。课堂原表独立归档只更新对应来源、定位与64条审核哈希，核对流程记录迁移前后逐格一致；原件未核与独立复审待完成的状态不变，数据版本随这些元数据变化重新生成。

## 录入与核对

登记版本和段落 → 录入或修改 → 实际核对 → 保存主体哈希与真实审核状态 → `npm run build:content` → `npm run check`。

- 审核`method`必须指向登记流程，每条记录明确保存ID、主体哈希、状态、`checkedRefs`和独有`issues`；构建与测试统一通过`readContent`读取资料，其中`readReviewFiles`读取分类审核、`expandReviews`合并共同问题。独立复核应新建流程并更新受影响记录，不能改共享流程冒充整批重审。
- 修改已核对对象或所引来源会使旧`subjectHash`失效，必须重新核对受影响条目；构建器不刷新审核或批准资料。无原文白话时省略`explanation`和`explanationRefs`，其审核为`not-applicable`；既有白话及爻位说明留档，爻位说明与审核ID成对提供。
- 已复现的字形异常须逐条对校后通写，保存原字、依据、旧问题及实际范围，只更新受影响哈希；不全库自动繁简转换，不提高影印或独立复审状态。具体通写与异文见[资料核对](../docs/content-review.md)。
- 课堂表独立保存在 [classroom.md](classroom.md)，来源 ID 为 `classroom-table`，定位按 `content/classroom.md／类别／卦` 登记；仅称课堂资料转录，不虚构原照片、教材页码或外部网址。每条对应在档案中保留体系与来源；先后天分开、季节原词保留、颜色允许并列。常用读音经编辑核对，重点多音字关联词典，无依据别名留空。
- 速查页面统一简体显示：构建时仅将经典卦性的“順／動／麗／說”映射为“顺／动／丽／悦”，页面按展示值去重；原典原词及其来源、体系、说明、先天数/方位和全部审核仍留档。该映射不改文献原文或提高审核状态。阅读来源面板仅展示文献标题、章节定位与“复制来源链接”，无网址不显示复制入口；完整版本、权利说明及引用备注继续留档。

## 构建与发布门槛

开发检查验证结构、引用、审核关联与哈希：每卦15个必需原文块，乾坤各另2块；检索64卦，八卦覆盖课堂8类及4类扩展，相生/相克各5条。未知JSON类别拒绝构建。资料测试自动覆盖全库，不逐批追加数量或整段原文断言。

结构版本为3；版本格式为`schemaVersion.内容哈希前12位`，完整SHA-256覆盖正文、来源、展开审核、检索、意象和生克。新资料主体为去掉`reviewId`后的记录，结合所引来源对象计算，检索另纳入别名引用；旧正文主体规则不变。相同源重复构建应逐字一致。

`npm run check:content:release`要求64卦/964原文块及完整查询资料、电子初核通过，并拒绝已标为needs-fix的问题。2026-10-22用户取消首版文献人工复审要求，影印、独立复审及释义人工审查不再阻断首版；记录和清单中的pending仍保留。旧门槛失败是历史事实，不改写成审核通过。开发与交付边界见 [README](../README.md)。

采用版本、异文、逐项待审及许可说明统一见[资料核对](../docs/content-review.md)与来源登记。卷页oldid只固定编排，不冻结嵌页；访问日、摘录与哈希记录实际采用范围，电子对校不称为影印核准。
